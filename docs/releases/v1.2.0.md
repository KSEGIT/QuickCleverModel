# v1.2.0 — proposed release

This is a release proposal for review. It does not publish a GitHub release or
tag. The changes below cover the work since v1.1.0 and the new packaging of an
already-tested TrueNAS installation.

## Changes since v1.1.0

- Move the pinned Prism runtime from `4dd165625` to
  `922be44aa6ac81b46f092716351cddff1c1733a7`. Use a two-stage CUDA build with
  pinned NVIDIA base-image digests and offline version reporting. The
  [runtime record](../runtime-versions.md) explains the pins and build limits.
- Add revision-pinned, SHA256-checked downloads and presets for Qwen3.5 9B/4B
  Q4_K_M and Granite 4.1 8B Q4_K_M. Track the Qwen3.5 template fix for Responses
  requests with multiple initial system/developer messages. Keep standard
  desktop/Linux model defaults separate from the TrueNAS preset.
- Add optional Qwen3.6 35B-A3B and Gemma 4 E4B browser-agent candidates, including
  explicit quantisation selectors. Their partial RTX results do not make them
  reliable defaults. See [browser models](../browser-agent-models.md) and
  [recorded results](../browser-agent-validation.md).
- Add API and real-client probes, fixture and live-web browser benchmarks,
  long-context and concurrency probes, a manual RTX benchmark workflow, and
  a results collector with a Pages dashboard. The `decide` suite compares
  free-text Qwen, schema-constrained Qwen and pinned GLiNER decision models;
  GLiNER runs on the CI runner's CPU. See the
  [benchmark guide](../benchmark-action.md) and [findings](../benchmarks.md).
- Add Codex CLI and Claude Code setup guidance and launch support. Preserve
  OpenCode MCP server configuration when updating its model configuration.
- Add the Linux updater with model/UI smoke checks, failed-update rollback,
  and a weekly systemd timer. Add Linux and macOS CI checks. TrueNAS custom
  apps use their own manual update and rollback procedure.

## Opt-in TrueNAS package

The new [TrueNAS guide](../truenas.md), `docker/compose.truenas.yaml`,
`docker/models.truenas.ini.in`, and `docker/truenas.env.example` package the
tested four-model setup. The YAML requires image/storage paths and secrets,
requires WebUI login, reserves the NVIDIA GPU, and defaults listeners to
loopback. It mounts weights and the preset read only and keeps WebUI data
persistent. Standard Linux/macOS presets remain unchanged.

Qwen3.5 9B starts at 64K with f16 GPU K/V. Qwen3.5 4B, Bonsai 27B 1-bit and
Granite 4.1 8B use 32K. Granite requests 32 GPU layers and q4_0 K/V; Bonsai
also uses q4_0 K/V. The app uses one resident model, one slot, four checkpoints,
ubatch 256 and a 256 MiB prompt cache cap. Container memory limits are 8 GiB
for inference and 2 GiB for WebUI, with no extra swap. Optional WebUI names
can show `(64K)` and `(32K)` while API IDs stay unchanged.

## Evidence and known limits

On 2026-10-25 the installed TrueNAS 25.10.7 app ran on an RTX 3070 with
8,192 MiB VRAM, Ryzen 5 5600X, about 15.55 GiB system memory, and NVIDIA driver
580.173.02. Its image was `quickclevermodel:de2ee56-truenas`, repository
revision `de2ee56`, reporting Prism `922be44`. The exact image identity is in
the [runtime record](../runtime-versions.md#truenas-deployment-identity).
Historical build provenance is unconfirmed. The newly documented tracked
Dockerfile build procedure needs its own target test.

- API contracts: **79/80 passed; aggregate FAIL**. Qwen9, Qwen4 and Bonsai each
  passed 20/20. Granite passed 19/20 and failed to use the second tool's result
  in a Messages conversation with two distinct tools.
- Long context: Qwen9 passed whole-line recall with 55,518 prompt tokens at an
  actual 65,536-token context. The final Qwen9 API run sampled a minimum of
  599 MiB free VRAM. Qwen4 passed the 32K recall probe. Bonsai failed recall
  at 32K; Granite failed at 64K. No tested 128K configuration passed all trial
  criteria. Context allocation is not a recall guarantee.
- Both containers were healthy, no final API run recorded a cgroup OOM event,
  and the app remained running. Authentication, local WebUI-to-API access and
  exact-origin checks passed. After display-label changes on 2026-10-26, all
  four stable IDs passed a short API chat smoke.

These checks do not establish a full CUDA configuration matrix, all-client
compatibility, a complete Qwen9 tool matrix, or reliability under concurrent
GPU work. Read the [validation record](../runtime-validation.md) before
changing a working model or advertising a tested context size.

## Migration and rollback

Download required weights before changing images. The legacy ternary
`Ternary-Bonsai-27B-Q2_0.gguf` does not load with current Prism. Fetch the
official separate replacement with `./fetch-models.sh bonsai`; keep both the
old Q2_0 file and the old image for rollback. Do not rename or patch the old
artifact into PQ2_0. The TrueNAS preset uses 1-bit Bonsai and does not expose
the ternary aliases. See the [format migration](../runtime-versions.md#ternary-format-migration).

For TrueNAS, preserve the old YAML, image, preset, secrets and WebUI data
backup before deployment. Render Compose privately before pasting it into
the custom-app editor. Restoring an app version does not restore bind-mounted
host data. Follow the [backup and rollback steps](../truenas.md#backup-update-and-rollback).
